## v1.11.8 — Production Hardening

Security-first production release. This is the first release gated by `npm run production:check` and the new tag-driven release workflow.

### Security fixes (fail-closed in production)
- **Removed** the hardcoded `'dev-secret-change-me'` SESSION_SECRET fallback. Centralized environment validation in `api/_lib/env.js` refuses to start the production API when required secrets are missing, and logs only secret **names** (never values).
- Dev mode generates an ephemeral random session secret per process; test mode uses a fixed non-production string. Both impossible to enable accidentally in production (`NODE_ENV`/`VERCEL` checked).
- **Forgot-password flow hardened**: reset tokens are now 32-byte random, 30-minute TTL, single-use; only a SHA-256 hash is stored in Redis/Upstash; plaintext token is **never** returned in HTTP responses in production. Dev opt-in via explicit `CRX_DEV_EXPOSE_RESET_TOKEN=1`.
- Admin password reset uses constant-time `timingSafeEqual` compare and requires `ADMIN_RESET_TOKEN` to be configured.
- All auth endpoints return generic responses to prevent account enumeration.
- `/api/health` reports coarse boolean configuration state only, never secret values.
- Placeholder secrets (`changeme`, `dev-secret-change-me`, `xxx`, etc.) are rejected at startup.

### Release workflow improvements
- **Production releases are now TAG-DRIVEN** (`vX.Y.Z`). A push to `main` runs CI verification only — it does NOT publish desktop/Android artifacts to users.
- **Android production signing guard**: all four keystore secrets (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`) are required; debug APKs are NEVER published to a production release; `jarsigner` verification confirms the APK isn't debug-signed; artifact existence verified.
- CI job runs `production:check`, `typecheck`, web + Electron build, Android debug build, uploads artifacts.
- Release job additionally builds + publishes signed desktop installers + signed Android APK.
- Upgraded `actions/setup-java` v4 → **v5**.

### Version consistency
- New `scripts/sync-android-version.mjs` keeps Android `versionName`/`versionCode` in lockstep with `package.json` automatically (1.11.8 → `versionCode 11108`).
- New `npm run production:check` script verifies version sync, absence of production fallbacks, tag-driven workflow, Android signing guard, basic secret scan.
- `npm run mobile:build` / `mobile:android` sync version before `cap sync android`.
